## 一、必须知道的三件事

### 1.1 你会在源码里找不到「抬手卡」——它在，但是另一个入口

敌人抬手卡在 `ui/monster_codex.py::_timing_card`（`:453`），调用点 `:173` / `:200`。**这个入口只在 `path_panel.py:1555` 被实例化**（点路线里的怪物圆点、出怪图标）。

用户日常打开的「图鉴」如果是从首页 `home_panel.py:43` 进的「怪物数据图鉴」，那是 **`ui/data_index.py::MonsterIndexView`（`:1550`）**，它的详情体在 `:1711` 只画了：

```
基础面板 / 抗性 / 免疫 / 技能 / 天赋·光环 / 批注
```

**没有抬手卡。** 这是用户报「图鉴里没有抬手」的真正原因，不是数据问题，也不是版本问题。

> 顺便：`data_index.py:1929` 里也有「状态机图鉴」（`statemachines`），是第三个入口。

### 1.2 干员确实有技能动画，之前的判断要修正

我上一版方案里写过「解包里没有技能动画」——**这句是错的**，基于两个样本（斯卡蒂、12F）下的结论，样本太窄。

实测 `char_002_amiya_defaultskin.json` 的 `Front` 组：

```json
"bakedMPDatas": { "Idle":…, "Attack":…, "Attack_Begin":…, "Attack_End":…,
                  "Die":…, "Start":…, "Default":…,
                  "Skill_Begin":…, "Skill":…, "Skill_End":…,
                  "Skill_2_Begin":…, "Skill_2":…, "Skill_2_End":… }

"bakedEvents": {
  "Attack":  {"eventTime": [0.633333], "events": ["OnAttack"]},
  "Start":   {"eventTime": [0.133333], "events": ["OnStart"]},
  "Skill":   {"eventTime": [0.0],      "events": ["OnAttack"]},
  "Skill_2": {"eventTime": [0.0],      "events": ["OnAttack"]}
}
```

敌人侧同样存在：1857 条里有 **59 只**的主取动画是 `Skill` 系列（`Skill` / `Skill_Begin` / `Skill_Attack` / `Skill_1_Loop_2` …），全量动画词表 104 种，其中 **32 种含 `Skill` 字样**。

**结论**：技能动画**能拿到**，方法是 `bakedMPDatas` 里的 `Skill*` 键 + `bakedEvents` 里对应的 `OnAttack`。
但要接受一个事实：**阿米娅的 `Skill` / `Skill_2` 抬手都是 `0.0`**（瞬间生效，没有前摇）。这是真实值，不是缺数据。

> 这条要写进图鉴：技能抬手 = 0 时显示「瞬发（无前摇）」，**不要显示成「未收录」**。

### 1.3 敌人侧的动画选择优先级必须扩展，否则会认错

现在的优先级是：

```
Attack > Combat > Attack* > *_Attack > Skill 上的 OnAttack
```

`Skill` 排在**最后一位**。对干员来说这是错的——干员普攻一定是 `Attack`，技能动画是 `Skill*`，两者需要**分开取**，不能塞进同一个优先级链。

**干员必须采两个独立值**：

| 字段 | 取法 |
|---|---|
| `a`（普攻抬手） | `bakedEvents` 里 `Attack` 或 `Attack_*` 的 `OnAttack` |
| `skills`（各技能抬手） | `bakedEvents` 里 `Skill` / `Skill_N` / `Skill_*_Begin` 的 `OnAttack` |

### B.3 解析规则（按此实现；实测结论，与最初设想的差异已标注）

1. **顶层**：`bakedAnimDatas` 是 dict，键是动画组。**实测：458 个文件有
   `Front` + `Back` 两组，7 个只有一组**（如 `char_1012_skadi2` 只有 `Default`，
   `char_102_texas` 只有 `Front`）。不能假设两组都存在，也不能假设一定叫 `Front`。
2. **每组**：`bakedEvents` 是 dict，键是动画名，值 `{eventTime: [...], events: [...]}`，
   两个数组**按下标一一对应**——必须同时取 `events[i]` 和 `eventTime[i]`，
   不能取 `eventTime[0]`（同一条动画可能有多个事件）。
3. **事件名要容错**：解包里有拼写错误。实测存在 `OnStrat`（2 处）、`OnSart`（2 处）、
   `Onstart`（4 处）。匹配时统一 `re.sub(r'[^a-z]', '', k.lower())` 后比较。
   **`beat` 事件必须忽略**（33 条，是节拍标记，不是攻击）。
4. **普攻抬手 `a`**：候选动画名优先级
   ```
   Attack > Attack_Loop > Attack_A > Attack_B > Attack_1/2/3 > Attack_C
          > Attack01/02 > Attack1/2/3 > Combat
   ```
   实测分布：`Attack` 382、`Attack_Loop` 37、`Attack_A` 17、`Attack_1` 8、
   `Attack1` 1、`Attack_1_A` 1、`Combat` 1、`Attack01` 1。
   **`Attack_Loop` 必须单列**——德克萨斯这类干员只有 `Attack_Loop`，漏了就误判成「无普攻」。
5. **技能抬手 `k`**：收集**所有以 `Skill` 开头且有 `OnAttack`** 的动画，保留原始名。
   实测 846 条 / 158 种名字，命名极不统一（`Skill_2_Loop` 103 次、`Skill_1` 91、
   `Skill` 63、`Skill_Down_2_Loop` 23、`Skill_2_Overload_Begin`、
   `Doll_Skill_1_SwitchIn`、`Skill_AllOutAttack_End`、`Skill_02`、`Skill3_Begin` …）。
   **所以不能硬编码「槽位 N → Skill_N」**，只能用正则 `[Ss]kill_?0*(\d)` 尽力提取槽位号，
   提不到就存 `null`，由图鉴按「精确 > 同前缀兜底（标推定）」匹配。
6. **Front/Back 一致性**：实测只有 **8 个**干员两组不同（`char_1045_svash2`、
   `char_117_myrrh`、`char_122_beagle`、`char_187_ccheal`、`char_193_frostl`、
   `char_241_panda`、`char_4042_lumen`、`char_421_crow`），差值 1~3 帧。
   主值取 `Front`，差异存 `fb: [前, 后]`。
   > 皮肤文件**不参与**交叉校验：`_defaultskin` 是图鉴基准姿势，皮肤可能换模型，
   > 拿皮肤去校验默认姿势只会制造假冲突。
7. **异常不中断**：单文件解析失败只累加 `errors`，不抛异常。

### B.4 覆盖率（已实测，不是估算）

`operators.json` 有 **463** 个干员（均有 `char_id`）。bake 目录
`zh_CN/gamedata/bakemuzzledata/character/` 共 **1566** 个文件 / **178.0 MB**，
其中 `_defaultskin.json` **465** 个 / **72.3 MB**，对应 **465** 个 charKey。

**bake 覆盖 463/463，一个不缺**；多出的 2 个（`char_008_owl`、`char_279_knit3`）
是未上线/内部单位，保留不删。

`with_timing = 448 / 465 = 96.34%`。剩下 **17 个不是数据缺失，是机制如此**：

| 归因 | 数量 | 成员 |
|---|---|---|
| `NO_ATTACK` | 7 | 吟游者：空 `char_101_sora`、浊心斯卡蒂 `char_1012_skadi2`、海蒂 `char_4045_heidi`、U-Official `char_4091_ulika`、魔王 `char_4134_cetsyr`、三角初华 `char_4184_dolris`；处决者：THRM-EX `char_376_therex` |
| `SKILL_ONLY` | 9 | 解放者：司霆惊蛰 `char_1043_leizi2`、玛恩纳 `char_4064_mlynar`、骋风 `char_445_wscoot`、龙舌兰 `char_486_takila`；阵法术师：圣聆初雪 `char_1046_sbell2`、蜜蜡 `char_344_beewax`、薄绿 `char_388_mint`、林 `char_4080_lin`、卡涅利安 `char_426_billro` |
| `DOLL` | 1 | 傀儡师：双月 `char_4124_iana`，普攻在 `Doll_Attack_Loop` 上，抬手 `0.1` |

**图鉴必须把这三种显示成机制说明，不能显示成「未收录」**——用户看到「未收录」
会以为是抓取失败，实际是这些干员本来就不这么打。

### B.5 体积约束（已达成）

原始 465 个文件 **72.3 MB**，派生表 **44.8 KB**（压缩 1650 倍）。
**绝不能把 `bakedMPDatas` 的 `trsData` 数组带进派生表**，那是逐帧浮点矩阵，
一份就几百 KB。派生表只存秒数、动画名、槽位号。

## 四、任务 C：干员图鉴加「抬手」栏

### C.1 位置（用户明确指定）

| 内容 | 放哪 |
|---|---|
| **普攻抬手** | 「基础面板」块内，紧跟 `攻击间隔` 之后 |

用户原话：「普攻击抬手帧数应该写在基础面板，技能抬手应该写在技能旁边」。

### C.2 实现位置

- 基础面板：`ui/data_index.py::OperatorIndexView`，面板数值渲染处（`_render_skills` 之前的「面板数值」卡）。
  - 现有关键字段来自 `operators.json` 的 `phases[elite][level]`，含 `attack_interval`。
  - **注意**：`operators.json` 顶层**没有** `attack_interval`，只有 `phases` 里每级有。取「当前所选精英/等级」那一级的值。
- 技能卡：`ui/data_index.py:1146 _render_skills`，在 `hd` 那一行的 `meta`（`tree_type` / `trigger_type`）旁边追加。

### C.3 显示格式（按此实现，已落地）

基础面板（`_render_stats`，追加到 `items` 末尾，与「攻击间隔」同格）：

```
生命上限 2680    攻击力 638     防御力 258    法术抗性 0
部署费用 18      再部署 70 秒   阻挡数 2      攻击间隔 1.500 秒
抬手 26 帧（0.867 秒）          登场 4 帧（0.133 秒）
```

技能卡（`_render_skills` 的 `hd` 行，紧跟类型标签）：

```
■ 战术咏唱·γ型   自动回复  手动触发   技能抬手 0 帧（瞬发）
■ 真银斩         自动回复  手动触发   技能抬手 8 帧（0.267 秒）
```

规则：

- `a == 0` → 显示 **「技能抬手 0 帧（瞬发）」**。**不要**显示成「未收录」或省略。
  实测有 5 个干员的普攻抬手为 0.0，阿米娅两个技能都是 0.0——这是真值。
- 该技能找不到对应 `Skill*` 动画（如斯卡蒂）→ **整条不显示**。
  不要写「无独立技能动画」占位，那会在大部分技能卡上挂一串灰字。
- 干员无普攻时，抬手格按 `r` 显示机制：`SKILL_ONLY` → 「仅技能期间有普攻」、
  `DOLL` → 「普攻在召唤物上」、`NO_ATTACK` → 「无普攻」。
- 完全查不到（`r` 也没有）→ 整条不显示。
- 三档帧号（`@30/60/120fps`）只在**敌人**图鉴的抬手卡里给。干员面板是 4 列网格，
  再塞三档会挤成两行，反而难读；干员这里只给 30 帧 + 秒。

### C.4 技能与 `Skill_N` 的对应（实测比预想乱得多，不要猜）

`Skill` / `Skill_2` / `Skill_3` 的**数字对应技能槽索引**（1 = `Skill`，2 = `Skill_2`）。
但实测 **158 种**动画名，大量不符合这个规律：

```
Skill_2_Loop(103)  Skill_1(91)  Skill(63)  Skill_2(60)  Skill_3_Loop(47)
Skill_Loop(42)  Skill_Down_2_Loop(23)  Skill_2_Attack(17)  Skill_3_Loop_A/B
Skill_2_Overload_Begin  Doll_Skill_1_SwitchIn  Skill_AllOutAttack_End
Skill_02  Skill3_Begin  ...
```

**已实现**（`operator_timing.skill_windup`）：

1. 先正则 `[Ss]kill_?0*(\d)` 提取每个动画的槽位号，与请求槽位相等的进 `exact`；
   同槽多个时优先名字含 `Attack` / `Loop` 的（那才是「打出去的那一下」，
   `Begin` / `End` 是起手和收招）。
2. 提不出号的进 `fuzzy`，**只有一个**时才当该槽位，返回 `fallback: True`，
   图鉴文案后缀「（推定：动画名）」。
3. 提不出号且不唯一的 → 返回 `None`，不硬塞。

玛恩纳实测：`Skill_2_Loop` → 2 号技能 8 帧，`Skill_1_Loop`/`Skill_3_Loop` → 16 帧。
