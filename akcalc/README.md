# 肥牛妙妙工具 · 明日方舟伤害与寻路

## 界面

深灰蓝配色，三档面板层次（窗口底 / 卡片 / 凹陷输入区），中文字体统一为
微软雅黑 UI、数字统一 Consolas。

* **顶部品牌栏**：应用名 + 副标题，右侧是干员数、缓存信息、同步全图鉴、下载敌人库；
* **胶囊标签页**：选中页签以强调色整块填充，取代传统 Notebook 边框；
* **卡片面板**：标题左侧有一道强调色竖条，卡片正文与边框之间留出内边距；
* **指标区**：单次伤害 / DPH / DPS 三个关键指标用强调色竖条 + 大号数字，
  其余指标灰字平铺，6 列 2 行，把竖直空间让给曲线；
* **曲线图**：曲线下方带渐隐面积填充，主次两级网格、圆角折线、圆点标记当前值，
  图例是右上角胶囊；破甲线与当前值各有一条竖虚线；
* **对比模式**：每个槽位顶部一根曲线色横条，与图中曲线一一对应；
* **原生标题栏**：通过 DWM 刷成与窗口一致的深色，不再是突兀的白色；
* **自适应尺寸**：启动时按屏幕工作区算窗口大小并居中，125% 缩放的 1080p 屏也不会溢出。

## 快速开始

### 方式一：直接运行 exe（推荐给普通用户）

双击 `dist\肥牛妙妙工具.exe` 即可，**无需安装 Python**。

* 单个 exe，约 30 MB，已内置 **463 位干员（含技能）+ 26 个关卡 + 2186 条敌人数据**；
* 首次启动会在 exe 同目录自动生成 `data\cache`（约 34 MB），之后**完全离线可用**；
* 若 exe 所在目录不可写（例如装在 `C:\Program Files`），
  缓存会自动改存到 `%LOCALAPPDATA%\ArknightsCalc`，功能不受影响；
* 想放到桌面/别的机器，**只拷贝这一个 exe** 就行。

### 方式二：从源码运行（开发用）

```bat
python run.py
```

首次运行需联网抓取干员与关卡数据，之后走本地缓存。

### 重新打包 exe

```bat
build_exe.bat
```

会自动把 PyInstaller 装到 `.build\pylibs`（**不污染系统 Python 环境**）、
生成图标、打包，产物落在 `dist\`。


一个纯 Python + Tkinter 的本地计算程序，包含两大功能：

| 功能 | 说明 |
|---|---|
| **伤害计算** | 物理 / 法术 / 元素 / 真实伤害，含穿透、增伤、5% 保底、DPH 与 DPS，以及 **10 种曲线**（伤害-防御/法抗/元素抗性、DPH-防御、DPS-防御/法抗、伤害-攻击力/倍率/穿透、DPS-攻速），可叠加技能曲线 |
| **寻路计算** | 读取真实关卡地图，按通行掩码求加权最短路，算出敌人从出怪口到目标点的路程与耗时 |

## 一、数据来源（重要）

### 干员数据：来自 PRTS Wiki ✅

- 站点：<https://prts.wiki>
- 方式：抓取干员页面的 `wikitext`，解析 `{{CharinfoV2}}`（职业/分支/稀有度/位置）
  与 `{{属性}}`（生命/攻击/防御/法抗/阻挡数/攻击间隔/信赖加成/潜能）模板
- 规模：`Category:干员` 全图鉴 **463 位**（其中 441 位含技能数据）；
  用 MediaWiki 的 `generator=categorymembers` 一次取 50 页，全量约 **40 秒**。
- 说明：PRTS 的 Cargo 数据查询接口当前不可用（返回 `internal_api_error_MWException`），
  因此改用模板解析。每个精英阶段 PRTS 只给「1 级」与「满级」两个锚点，
  中间等级按**线性插值**补齐（游戏内本来就是线性成长）。
  - 精英 1/2 阶段 PRTS 不给 1 级数值，本程序以上一阶段满级为起点插值，
    结果单调连续（实测：能天使 E0‑50 = E1‑1 = 1016 HP / 305 攻）

### 地图数据：来自 PRTS Map 的同源原始数据 ⚠️

必须如实说明：

- **`map.prts.wiki` 子站已经无法访问**（DNS 无法解析），PRTS 的关卡页面本身
  也**不包含任何格点数据**——只有地图尺寸（如 `11×7`）、敌人情报和关卡装置列表。
- 因此本程序改用 **PRTS.Map 当初渲染的那份游戏原始数据**：

  ```
  https://github.com/Kengxxiao/ArknightsGameData
  zh_CN/gamedata/levels/obt/<分类>/level_<关卡id>.json
  ```

  这是客户端解包结果，字段与 PRTS.Map 完全一致：
  `mapData.map`（格子矩阵）、`mapData.tiles`（`passableMask` / `heightType` /
  `buildableType`）、`routes`（路线与检查点）、`options`（`moveMultiplier` 等）。

  **所以渲染出的地图与 PRTS.Map 看到的是一样的**，只是数据取自解包仓库而非已下线的子站。

- 敌人面板取自 `zh_CN/gamedata/levels/enemydata/enemy_database.json`（约 15 MB，可选下载）。

### 固定 API（获取干员数据）

想从别的脚本/工具里取干员数据，直接调 PRTS 的 MediaWiki API 即可，
下面是本程序实际使用的三个端点（均已验证可用）：

**1) 列出全部干员名**

```
https://prts.wiki/api.php?action=query&list=categorymembers
    &cmtitle=Category:干员&cmlimit=500&format=json&formatversion=2
```

**2) 批量取 wikitext（推荐，一次 50 页）**

```
https://prts.wiki/api.php?action=query&generator=categorymembers
    &gcmtitle=Category:干员&gcmlimit=50&gcmnamespace=0
    &prop=revisions&rvprop=content&rvslots=main
    &format=json&formatversion=2
```

返回里正文位置：`query.pages[i].revisions[0].slots.main.content`；
翻页用返回的 `continue.gcmcontinue` 回填 `gcmcontinue` 参数。

**3) 单页 wikitext**

```
https://prts.wiki/api.php?action=parse&page=克莱门莎&prop=wikitext
    &format=json&formatversion=2
```

**本地用法**：

```bat
python sync_operators.py                 :: 增量同步（只补缺失）
python sync_operators.py --all           :: 全量重抓
python sync_operators.py 克莱门莎 能天使   :: 只抓指定干员
```

程序内的「同步全图鉴」按钮走的就是同一套逻辑。
也可以直接用 Python 调用：


## 二、伤害计算

### 公式（严格按 PRTS「游戏数据基础」）

```
基本伤害   A = 攻击力 × 攻击力倍率 + 附加攻击力

物理       DMG = max(0.05A,  A − (1−Ip)·max(0, D − Iv))
法术       DMG = max(0.05A,  0.01A · max(0, 100 − (1−Ip)·max(0, D − Iv)))
元素       DMG = max(0.05A,  0.01A · max(0, 100 − D))
真实/治疗  DMG = A
```

- `Ip` = 百分比穿透（0~1），`Iv` = 固定穿透
- `D` = 目标防御力 / 法抗 / 元素抗性（法抗与元素抗性以**点数**计，100 = 免疫）
- `0.05A` 是**保底伤害**，任何情况下都不会低于它

### 攻速

```
实际攻击间隔  T = T₀ / (clamp(S, 10, 600) / 100)
```

`T₀` 为理论攻击间隔（PRTS「攻击速度」字段），`S` 为攻速值，默认 100。
注意攻速属性的**实际下限是 20**（clamp 写的是 10，但属性本身不会低于 20）。

### 校验示例（能天使 E2‑90 满信赖，攻击 540 + 信赖 90 = 630）

| 目标防御 | 单次伤害 | 说明 |
|---:|---:|---|
| 0 | 630.00 | 630 − 0 |
| 200 | 430.00 | 630 − 200 |
| 500 | 130.00 | 630 − 500 |
| 1000 | **31.50** | 已触底 = 5% × 630 |

破甲线（刚好触底所需的防御）= `0.95 × A` = **598.5**

法术校验（艾雅法拉 E2‑90，A = 735）：法抗 0 → 735；法抗 50 → 367.5；法抗 100 → 保底 36.75。

### 曲线

右侧「伤害曲线」下拉可选 **10 种曲线**，全部由 `core/curves.py` 统一生成，
每条曲线的每个采样点都直接调用 `compute_damage`，所以**曲线端点与单点计算结果必然一致**
（已回归验证：防御 0/100/200/500/1000/2000 → 630/530/430/130/31.5/31.5）。

| 曲线 | 横轴 | 纵轴 |
|---|---|---|
| 伤害 - 防御 | 防御力 0 ~ 3000 | 单次伤害 |
| 伤害 - 法抗 | 法抗 0 ~ 100 | 单次伤害 |
| 伤害 - 元素抗性 | 元素抗性 0 ~ 100 | 单次伤害 |
| DPH - 防御 | 防御力 | **每次攻击总伤害**（含连击） |
| DPS - 防御 | 防御力 | 伤害 / 秒 |
| DPS - 法抗 | 法抗 | 伤害 / 秒 |
| 伤害 - 攻击力 | 面板攻击力 | 单次伤害 |
| 伤害 - 攻击力倍率 | 倍率 0 ~ 5 | 单次伤害 |
| 伤害 - 穿透 | 百分比穿透 0 ~ 100% | 单次伤害 |
| DPS - 攻速 | 攻速 10 ~ 600 | 伤害 / 秒 |

- 横轴上限可手填（留空用默认）；
- 物理曲线会叠加 **5% 保底线**（灰色虚线）并标出**破甲线**（橙色竖线）；
- 勾掉「叠加保底线」可只看主曲线。

### 对比模式（至多 5 位干员同框）

勾上曲线区右上角的「**对比模式**」，下方会展开 5 个槽位，每位干员各占一列：

| 槽位里的控件 | 说明 |
|---|---|
| 干员名（可输入） | 463 位全图鉴都能选，与上方分类筛选互不影响 |
| 精英 / 等级 | 各自独立，允许 E1‑50 和 E2‑90 同框比较 |
| 技能 / 技能等级 | **每位干员可以开不同的技能**，等级档位跟随所选的技能 |

- 每条曲线用**固定配色**：1 蓝、2 红、3 绿、4 黄、5 紫，图例在左上角；
- 横轴上方黄竖线是当前目标抗性，每条曲线在该处**各自标注数值**；
- 曲线下方的汇总行按 DPS 降序排列，一眼看出谁高；
- 只填 1 位时退化成单条曲线，清空所有槽位则只提示、不报错；
- 「填入当前」把单干员模式的选择一键搬进第一个空槽，「清空」一键清 5 位；
- 穿透 / 增伤 / 攻速 / 目标抗性 / 伤害类型是**公共条件**，所有干员共用；
  攻击力、攻击间隔、连击、技能倍率则各按各的数值算。

> 实测：能天使 E2‑90 开 S2 过载专三，对比框里 DPS 3160、DPH 2465，与单干员模式
> 单独算的结果完全一致。

## 三、寻路计算

### 规则

- 敌人用**加权最短路**寻路（游戏内是 SPFA，与堆优化 Dijkstra 结果等价）
- **地面**单位只走地面通行掩码，**飞行**单位走飞行通行掩码
- **类障碍物地块**寻路代价 = `1000`，**地穴** = `1,000,000`，
  普通地块 = `1`；斜向移动代价再乘 `√2`
- 移动速度：

  ```
  每帧位移 = 移速 × moveMultiplier / 帧率
  实际每秒 = 移速 × moveMultiplier
  ```

  `moveMultiplier` 从关卡 `options` 读取（实测 1‑7、4‑4 均为 0.5）
- 移速下限 0.1（游戏内不存在速度上限）

### 三个必须处理的数据坑

#### 坑 1：`map` 矩阵的行序是**自下而上**

关卡 JSON 里 `mapData.map[0]` 是地图**最下面**一行，而 `routes` 里的
`startPosition` / `checkpoints` 坐标以**最上面**为 `row 0`（与 PRTS.Map 显示一致）。
两者方向相反，解析时必须把 `map` 矩阵上下翻转。

实测（26 个关卡、828 条路线）：

| 处理方式 | 可达路线 |
|---|---|
| 不翻转 | 696 / 828 |
| **翻转 `map` 行序** | **828 / 828** |

且翻转后没有任何关卡变差，因此这不是凑数，而是数据本身的方向约定。

#### 坑 2：`WAIT_*` / `DISAPPEAR` 检查点的坐标是占位值

路线里只有 `MOVE` 与 `APPEAR_AT_POS` 两类检查点的 `position` 带真实坐标。
`WAIT_FOR_SECONDS`、`WAIT_CURRENT_FRAGMENT_TIME`、`DISAPPEAR` 的 `position`
**一律是 `(0, 0)`**，只贡献停驻时间。如果把它们当作途经点，每条带停驻的路线
都会被算成「绕经左上角」，表现为大面积假不可达。

`APPEAR_AT_POS` 是**瞬移**：敌人直接在落点出现，这一段**不计移动路程**，
界面上用虚线 + 空心圈标记。`DISAPPEAR` 表示敌人当场离场。

#### 坑 3：出怪口与目标点被标成不可通行

在解包数据里，**出怪口和保护目标点经常被标成 `tile_forbidden` + `FLY_ONLY`**
（位于地图边缘的「虚空行」）。但敌人实际能从那里生成并走入地图。
本程序因此把这些格**强制视为可通行**，否则会出现「35 条路线全部不可达」的假象。

### 界面操作

1. 顶部选关卡 → 点「加载地图」（首次下载后缓存到本地）
2. 地图渲染：深蓝=地面，灰=高台，褐=墙，红点=出怪口，绿点=目标点
3. 勾选「地面层 / 飞行层」切换通行性着色，「显示代价」标出 1000 / 1e6 的格子
4. 点右侧任一列路线 → 地图上黄色高亮该路线，状态栏显示路程与耗时
5. 点地图任一格 → 右侧显示该格的地块类型、通行性、寻路代价
6. 点「本关敌人」列表中的敌人 → 自动切到伤害页并填入其面板

### 校验（1‑7）

- 地图 11×7，地面 30 格、飞行 77 格，26 条地面路线
- 每条路线路程 12.00 格，`moveMultiplier = 0.5`，移速 1.0
- 耗时 = 12 / (1.0 × 0.5) = **24.00 s**，与游戏内实际吻合
- 全部 26 个已缓存关卡、828 条路线：**828/828 可达**

## 五、已知限制

1. **法术的 0.01 略小于标称值**：PRTS「定点数与浮点数」指出实际存储约 `0.00999999997`，
   本程序默认用标称 `0.01`；需要完全复刻游戏时可在 `constants.py` 里换成
   `ELEMENT_RATIO_EXACT`（差异约 −0.3e-7，对结果无实际影响）。
2. **移速不检查落点可通行性**：游戏内单位沿路径移动时不检测终点格是否可通行，
   本程序保持一致；因此极端情况下路径末端可能落在不可通行格。
3. **阻挡判定用平方半径**：地面 `0.49999037`（对应半径 0.70709997），
   飞行 `0.79995137 × 倍率²`。直接比较半径会得到错误结果，本程序用平方值比较。
4. **阻挡偏移的「0.2」有歧义**：PRTS 原文「产生不超过 0.2 距离的、表现为旋转的
   阻挡偏移」既可理解为「额外旋转量上限 0.2」，也可理解为「相对原位的总位移上限 0.2」。
   `blocking.apply_block_offset(..., secondary_mode=...)` 同时支持两种：
   默认 `"additional"`（额外量），可传 `"total"`（总量）。
5. **技能是「尽力而为」解析，天赋不解析**：`core/skills.py` 与
   `core/skilldata.py` 能从官方技能表抽出攻击力倍率、附加攻击力、攻速、
   攻击间隔修正、连击数、持续与技力，并已专门处理两类易错语义：

   - **条件加成不计入无条件倍率**：描述写「第二次及以后使用时追加
     攻击力 +30%」时，blackboard 里 `xxx[b].atk = 0.3` 只有第 2 次施放
     才生效，不能直接乘进面板倍率（艾雅法拉「二重咏唱」曾因此被算成
     `x1.60 + 2 连击`，实际是 `攻速 +30` 的纯攻速技能）。
   - **「次」不都是连击数**：「每次部署后可发动 4 次技能」「可以充能
     2 次」「第二次及以后」里的数字都与连击无关，已按分句剔除。

   仍然**不会自动生效**的：天赋增伤、位置/目标数量等条件效果，
   需要在「加拐」区手动填入「增伤 / 穿透」。
6. **地形对伤害无影响**：高台/地面只影响可部署位置，不影响伤害数值。
7. **敌人攻击类型默认物理**：法伤敌人由技能实现，未逐条解析，可手动改伤害类型。
8. **关卡清单是常用子集**：`maps.COMMON_LEVELS` 内置 29 个已验证的常用关卡；
   要加载其它关卡可在代码里调用 `maps.get_level("<level_id>", "<分类>")`。
   注意关卡 ID 必须真实存在（如 `main_13-05`、`hard_12-01`），
   早期试探用的 `main_09-19`、`hard_01-01` 等在数据仓库里返回 404。
9. **医疗干员不算输出**：面板的伤害类型只有物理/法术/元素/真实四档。
   医师、群愈师等分支切进来时会标注「医疗干员，不造成伤害」，结果栏的
   DPS 显示 `—`，不给一个看着像伤害的数字（治疗量可参考单次伤害）。
10. **「法术」不等于法伤**：技能描述里的「法术」有一半是在讲**防御**，
    例如银灰「获得法术闪避」、夜莺「法术抗性提升」、塞雷娅「附近所有
    敌军受到的法术伤害 +20%」（她在增伤，不输出）、深律「停止攻击并
    专心治疗」、以暴制暴「对自身进行治疗」（自我回血）。这些都已显式
    排除，不会把物理干员判成法术干员。同理「伤害类型变为 真实」这类
    改写也会被单独识别（策略：熔毁、奇美拉）。
11. **减防与穿透是两个独立乘区**：`def_down`（减防 %）乘在目标防御上，
    只作用于物理；`def_flat` / `def_pen` 是固定/百分比穿透。它们现在都是
    `DamageInput` 的正式字段，**没有**在调用方预先折算——曲线按「原始
    防御力」当横轴逐点扫描，提前折算会被扫描覆盖掉（表现为「填了减防
    但曲线不动」）。
